# 受付番号（2026-09-26導入）

受付登録時に16桁の文字列を発番し、`Reception.receptionNo` に保存する。

`88 + センターコード4桁 + JST年月日6桁（YYMMDD）+ センター日次連番4桁`

例: `8831012609260001` は狭山（3101）、2026年9月26日、1件目。NHSの通常番号は04で始まり、残りの構成は同じ。NHSへの実登録は別途検証が必要。

- `CenterDailyCounter` の更新と受付作成は同一トランザクション。削除しても採番カウンタは戻さない。
- 既存受付の最大日次番号も読み、カウンタ導入前のデータや切替中の旧サーバーから続番にする。
- 9999を超える場合は登録せず503を返す。センターコードが4桁の数字でなければ登録前に400を返す。
- 受付日時・日付キー・番号・会計年度は同じ日時のJST表現から算出する。
- DBのユニーク制約を使用。導入前の受付番号はNULLのまま保持する。
- キオスク完了画面・受付票・QR・管理一覧・CSVは同じ保存値を使う。短い日次番号は呼出番号として残す。
- CSVの受付番号は16桁なので、Excelでは文字列型として取り込む。

DB反映は `prisma/migrations/20260926070000_reception_number/migration.sql` の追加のみ。既存データへの更新や、全体のdb pushは不要。

検証: `npm test`、`npm run build`。実DBの検証は独立したテスト用スキーマを使い、同時12件、削除後の続番、既存番号の継続、センター別連番、上限、登録失敗のロールバックを確認。ブラウザで登録ボタンから完了画面・印刷HTML・QR復号・管理画面検索を確認する。
