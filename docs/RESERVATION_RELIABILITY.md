# 予約検索・予約日・再送・タッチ操作の修正

## 動作

- ドライバー予約は電話番号とプレート4項目を保存する。旧予約の電話番号が空欄なら、紐づくDriverの電話番号から検索する。車番の分解項目も必要時に補完する。
- 予約日はJSTの午前0時で保存する。検索・定員判定はJSTの当日24時間を対象にし、旧UTC午前0時の予約も同じ業務日の予約として扱う。翌日のJST午前0時は含まない。表示と編集もJSTにそろえる。
- 受付・ドライバー予約に送信ごとのrequestIdと入力内容のrequestHashを保存する。同じID・同じ内容の再送には保存済みの同じ結果を返し、異なる内容・別ドライバーのID流用は409で拒否する。
- 受付の人物・車両・日次番号・受付・予約チェックインは一つのトランザクションで確定する。外部通知や使われていない集計の失敗で、保存済みの受付を失敗にしない。
- ドライバー予約の成功表示はプロフィールの既定値保存と切り離す。既定値保存の失敗時にも予約完了を維持する。
- 成否不明時は、再試行・再読込でも同じ送信IDと入力内容を使う。完了画面からの明示的な移動・予約取消成功後には次の予約用に保持状態を解除する。
- 人物・車両・予約の候補はタップ完了時に選択する。指を置いたままの縦スクロールは選択として扱わず、Enter/Spaceでも選べる。
- 最終確認から同じ電話番号を確認し直しても予約を保持する。電話番号が変わった場合は旧人物・車両を消して検索し直す。検索失敗と候補0件は区別する。

## DB反映

`prisma/migrations/20260926070000_request_idempotency/migration.sql` はReservationとReceptionへ、それぞれnullableのrequestId・requestHashとrequestIdの一意インデックスを追加する。既存の予約日・電話番号・受付番号の書き換えは不要。

アプリ更新前に追加DDLを適用する。ロールバック時は以前のアプリへ戻し、追加列を残せる。既存データを削除するdb:pushは使わない。

切替前の端末との互換性のため、APIはrequestId省略を受け付ける。旧画面からの無予約受付は再送防止の対象にならないため、反映後は受付端末・ドライバーの画面を再読込する。

## 検証

- 単体テスト：日付境界、旧電話空欄、車番分解、同IDの再送・内容不一致・並行競合、予約状態更新失敗時の全体巻き戻し、外部通知失敗後の成功応答。
- 独立した検証DBとVercelプレビュー：予約・受付の各8件同時送信が1件へ収束、定員1枠への同時予約、UTC/JST混在日の管理一覧・空き枠・スマホ表示、旧予約の電話検索、16桁受付番号の維持。
- ブラウザ：人物・車両・予約のタッチスクロールとキー操作、同番号の予約保持、番号変更時の再検索、検索HTTP500、予約後のプロフィール通信失敗、応答消失後の再読込・同じIDでの再試行、取消後の再予約。

実機プリンター、手袋での操作、iOS/Android各端末での実操作は別途確認する。
